# protoc-gen-go-deepcopy

`protoc-gen-go-deepcopy` is a plugin for protoc which generates `DeepCopyInto()`, `DeepCopy()` and `DeepCopyInterface()` functions for .pb.go types.

It is a fork of [protobuf-tools/protoc-gen-deepcopy](https://github.com/protobuf-tools/protoc-gen-deepcopy), kept in this repository so that the generated code can be corrected and extended here rather than pinned to an upstream release. The change made so far is described under [Difference from upstream](#difference-from-upstream).

The directory name is load-bearing: protoc invokes a plugin named `protoc-gen-go-deepcopy` as `--go-deepcopy_out`.

## Generated

```proto
syntax = "proto3";

package generated;

option go_package = "github.com/onexstack/protobuf-go-plugins/cmd/protoc-gen-go-deepcopy/testdata/generated";

// TagType for ensure DeepCopyInto method is created.
message TagType {
    uint32 fieldA = 1;
    string fieldB = 2;
}
```

```go
// Code generated by protoc-gen-go-deepcopy. DO NOT EDIT.

package generated

import (
	proto "google.golang.org/protobuf/proto"
)

// DeepCopyInto supports using TagType within kubernetes types, where deepcopy-gen is used.
func (in *TagType) DeepCopyInto(out *TagType) {
	proto.Reset(out)
	proto.Merge(out, in)
}

// DeepCopy is an autogenerated deepcopy function, copying the receiver, creating a new TagType. Required by controller-gen.
func (in *TagType) DeepCopy() *TagType {
	if in == nil {
		return nil
	}
	out := new(TagType)
	in.DeepCopyInto(out)
	return out
}

// DeepCopyInterface is an autogenerated deepcopy function, copying the receiver, creating a new TagType. Required by controller-gen.
func (in *TagType) DeepCopyInterface() interface{} {
	return in.DeepCopy()
}
```

## Difference from upstream

Upstream generates `DeepCopyInto` as:

```go
func (in *T) DeepCopyInto(out *T) {
	p := proto.Clone(in).(*T)
	*out = *p
}
```

`*out = *p` is a struct assignment, and a generated message embeds `protoimpl.MessageState` — which holds a `sync.Mutex` and an atomic pointer. The assignment copies that state, so the copy and the original share one mutex. It is not a `go vet` false positive: it is a data race the moment either message is used concurrently.

`proto.Clone` is not the culprit — it builds its result with `New()` and `mergeMessage`, and never copies state. Only the following assignment was wrong.

This fork goes through the reflection API instead: `proto.Merge` writes field by field without touching the state, and `proto.Reset` clears `out` first so that a non-zero destination does not keep fields the source lacks. The generated import and the three method names are unchanged, so consumers need no edits.
